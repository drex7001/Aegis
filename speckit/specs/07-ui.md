## 1. Strategy — one app, grown in place

There is **one** UI: `ui/` — React 18 + TypeScript + Vite, started in Phase 2
and grown through every later phase. No interim server-rendered stack, no
throwaway panels, no parallel UI generations (ADR-023's replace-never-extend,
applied to our own work). The legacy Cytoscape explorer and its anonymous
`/api/*` surface are deleted in Phase 2 when the workspace's graph view lands
(ADR-026).

| Phase | The same app gains |
|---|---|
| **P2** | Auth shell (Keycloak OIDC PKCE), source landing/extraction status, review queue (typed suggestions), identity adjudication, graph view + provenance panel, entity search |
| **P4** | Object views (entity-360), cases, hypotheses, tasks/leads, timeline + as-of mode, case-centric layout |
| **P5** | Map view (MapLibre) synced with timeline/graph |
| **P6** | Global search, object-set builder, findings panel, watchlist triage |
| **P7** | Redaction preview, compartment UX, break-glass flow |
| **P8** | Assistant surfaces (citation-first) |

## 2. Technical shape (P2 — ADR-032)

- **Auth:** `oidc-client-ts` / `react-oidc-context` (Article XII — no
  hand-rolled OIDC state machine). Tokens held in memory, never localStorage;
  silent renew per the library; logout revokes; CSP + security headers served
  with the app; idle/absolute session timeouts configured in Keycloak.
  T41 found the last of those **undeclared** — the realm ships no
  `ssoSessionIdleTimeout` or `ssoSessionMaxLifespan`, so it runs on Keycloak's
  defaults. That, the CSRF model (bearer-only, no ambient credential), and
  multi-tab behaviour (`monitorSession: false`, in-memory user store — each tab
  holds its own session) are the H-19 remainder, closed at T42 and specified in
  spec 09 §10.
  Landed at T22 with two consequences worth stating: the **PKCE state** (code
  verifier + nonce) lives in sessionStorage because it must survive a full-page
  redirect — tokens never do; and a **page reload therefore re-authenticates**
  through the SSO session rather than restoring a persisted token.
- **API client:** generated from the FastAPI OpenAPI document (stable
  operation IDs are an API convention from P2). The P3 ontology-aware client
  (`sdk/ts/`) replaces it types-first, with no screen rewrites.
- **Data:** TanStack Query (or equivalent) for fetching/caching; no global
  state framework until a real need appears.
- **Navigation:** path-based. P2 routed on the History API directly
  (`src/routing.ts`) — two views did not need a router, but they did need real
  URLs, a working back button and a path the auth guard could return to.
  **`react-router` landed at T42**, when `/types/:name` made the parameter real.
  The hazard P2 named was that the sign-in callback rewrote the URL with
  `replaceState`, which a router cannot observe; T42 removed it rather than
  worked around it — the callback records `returnTo` and
  `auth/SigninCallback.tsx` navigates through the router with `replace: true`,
  so there is exactly one owner of the URL. `src/routing.ts` keeps the route
  table and its path builders, so a link is never a hand-written string.
- **Ontology vocabulary is fetched, never hard-coded** (Article XI):
  `GET /v1/ontology/vocabulary` supplies handling codes and source types to the
  forms that need them. A picker written into the bundle is a second domain
  artifact that keeps working, and keeps being wrong, after the ontology moves.
- **Graph canvas:** Cytoscape.js inside React (exists, works; Sigma.js only
  behind the plan §2 WebGL trigger). Reads `POST /v1/graph/expand`. Layout is
  deterministic per element set, so the same query redraws the same picture and
  two runs are comparable.
- **Quality bar:** function over polish in P2 — cosmetic work is P4's;
  type-check + build + one demo-loop e2e in CI.

## 3. Ontology-driven screens (Article XI — P4)

Generic components render from the **generated descriptor module**
`ui/src/api/ontology.ts` — object types with `display` and per-property
metadata, interfaces, categories and predicates, emitted by
`aegis ontology generate` and guarded by its CI drift gate. There is no
`ui_meta.json`: Phase 3 already generated the module, and a second artifact
carrying the same facts would be a second drift risk whose contents no
type-checker sees (**ADR-043**, spec 09 §6.2). The contract in full is spec 09
§6; what follows is what the screens do with it.

Because the descriptors are compiled into the bundle, they cannot know the
server moved. `ONTOLOGY_VERSION` is compared against
`GET /v1/ontology/vocabulary` and a mismatch raises a persistent, non-blocking
banner naming both versions (spec 09 §6.3).

- **Entity page**: title/subtitle from `display`; claims grouped by predicate;
  each claim row shows assertion type, grading chips (reliability /
  credibility / verification — Article III), validity window, source link,
  contradiction badge.
- **Claim detail**: full provenance — excerpt, source record, derivative chain
  down to the original file; relations; retraction state.
- **Forms**: create/edit claim drafts built from ontology property/predicate
  specs and action parameter schemas (P3) — adding `vessel` to a domain module
  yields a working vessel page with no new UI code. Evaluate
  JSON-Schema-driven form generation (e.g. RJSF) before hand-building (H-20);
  bespoke code is reserved for provenance, conflict display, and governed
  actions — the surfaces that *are* the product.

Descriptors describe the **ontology**, never the screen — no layout, ordering,
widths, icons or tab assignments. That line is what keeps generation from
becoming a second UI codebase written in YAML (H-20).

## 4. Workspace layout (P4 — GOAL.md §30 scaled)

```
┌──────────────────────────────────────────────────────────┐
│ Search │ Case switcher │ Review queue (badge) │ Profile   │
├────────────┬─────────────────────────────────────────────┤
│ Case nav   │           Active view                        │
│ Entities   │   Graph  /  Timeline  /  Map (P5)  / Table   │
│ Claims     │                                              │
│ Evidence   │                                              │
│ Hypotheses │                                              │
│ Tasks      │                                              │
├────────────┴──────────────────────────┬───────────────────┤
│ Selection details (claims, history)   │ Provenance /       │
│                                       │ Why connected?     │
└───────────────────────────────────────┴───────────────────┘
```

P2 shipped the same skeleton without the case column (top bar + active view +
detail/provenance panels).

**T42 landed the rail.** Two groups, both of them live destinations: *Workspace*
(Sources, Review, Graph) and *Ontology* — every declared object type and
interface, listed from the generated descriptors and nothing else
(`layout/OntologyNav.tsx`). Each type and interface has a screen behind it
(`/types/:name`, `/interfaces/:name`) rendering what the ontology says it is:
properties with their labels, types, cardinality, clearance and conflict policy;
the interfaces it implements; and every predicate that can attach to it, grouped
by category with the ontology's own colour. Those screens call **no endpoint** —
they are the descriptors rendered — which is what makes "add a type to a domain
module and a working screen appears" checkable before T44's entity-360 exists.

**T46 filled the case column.** The switcher lists the caller's own cases from
`GET /v1/cases` — no count, because a total over an authorization-filtered
collection is an existence leak, and an empty list reads "you are not a member
of any case" rather than "none exist". `/cases` and `/cases/:id` sit behind it:
membership, closing, references, and a **case-scoped graph** that asks the
server for that case's evidence (`case_id` on `/v1/graph/expand`) rather than
filtering a graph it was handed.

The case screen states ADR-044 where an analyst reads it: a reference grants no
access to its target and does not move a claim into the case. Calling references
"the case's claims" would teach the reader the opposite of how access works.

Above the active view sits the **ontology-version banner** (spec 09 §6.3):
`ONTOLOGY_VERSION` from the bundle against `GET /v1/ontology/vocabulary` from
the server, non-blocking, in the caution bronze — the data is current, only the
captions may be stale.

## 5. Interaction principles (binding — GOAL.md §30)

- Search first, expand second; expansion always bounded (hops/types/time/confidence).
  Until entity search lands (T23c) the canvas opens on a **bounded overview** —
  an authorized, capped, deterministically ordered slice. It is subject to the
  same element budget as any expansion, which is what keeps it from being the
  bulk dump ADR-026 retired.
- Every claim opens its source; every metric shows its caveat (Article IX).
- Suggested (machine) material is visually distinct from recorded claims —
  different styling, separate legend entry; never mixed silently into the
  canonical view (Article VII).
- Contradictions are a visible lens, not a footnote (Article VIII).
- Current vs historical state clearly separated; as-of mode has a persistent
  banner stating exactly what the snapshot holds constant (B-11).
- No red-means-criminal styling; categories use the ontology palette.
- **Only the exceptional state is marked** (T23a). A left rail means "this needs
  you" and nothing else — the same device on a graph notice and on a quarantined
  record. Ordinary records keep the geometry and drop the colour, so a register
  stays scannable and a mark still means something. A governance hold is not an
  alarm: quarantine uses the caution bronze, never the failure colour, which is
  reserved for a request that failed and is never applied to an entity, a
  category or a claim.
- **Monospace is reserved for machine identities** — content hashes, record ids
  — where character-by-character comparison is the point. Prose stays in the
  body face. The digest chip is what makes "already landed" credible: the
  operator can see that the hash coming back is the hash of what they sent.
- Restricted data is absent, not teased (no "N hidden" counts — specs/03 §4;
  marked-redaction and counts modes are P7 policy decisions, H-25).
- Retained from the prototype (as *requirements*, not code): layer/category
  toggles, confidence filter, temporal slider with play, cell coloring,
  source-cited detail cards.
